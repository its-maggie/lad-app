# 全站最近更新

網站頂部的「最近更新」在排期、計算機和記帳分頁都能查看。尚未讀過的公告會自動展開；點「已讀並收起」或「收起更新」後，這台裝置的瀏覽器會記住已讀狀態。仍可點「查看更新」重看，之後有新的公告 id 就會再次展開。這是站內通知，不需要瀏覽器推播權限。

## 每次手動發布

1. 修改網站內容。若是排期，更新 `schedule.js` 和 `SCHEDULE_META.updated`，已確認的項目設為 `tentative: false`。
2. 在 `updates.js` 的陣列最前方新增一筆公告；保留之前的紀錄。
3. 使用全新的 `id`（同日第二次更新也要換 id）和台北日期。`items` 可同時包含排期與功能。
4. 測試後一起 commit、push。既有 GitHub Actions 會測試並部署至 Vercel。

```js
{
  id: "2026-10-03-schedule-2",
  date: "2026-10-03",
  items: [
    { type: "schedule", title: "活動名稱｜日期已確認", body: "說明調整前後的日期。" },
    { type: "feature", title: "功能名稱", body: "說明使用者現在能做什麼。" }
  ]
}
```

不要直接重用舊 id 改公告，否則已讀訪客不會再次收到提醒。正式發布後的更正也請另發公告。

## 官方同步

現有 `Sync official schedule` 工作流程由 GitHub Actions 手動觸發。成功確認並修改排期時，會一併產生 `updates.js` 公告並部署。dry run 或沒有異動時不寫入公告；無法確定的排期仍沿用原本的人工確認流程。

此通知功能不會新增官方資料抓取排程。網站的排期與公告檔案設為每次重新驗證快取，訪客重新開啟或重新整理網站即可取得新版本。

```bash
node --test scripts/*.test.mjs
```
